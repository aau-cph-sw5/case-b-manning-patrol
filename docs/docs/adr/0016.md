# ADR 0016. Permission-Based Access Control decision.

**Status.** Proposed 
**Date.** 2026-11-20
**Deciders.** Group 3 - Héðinn Snær Arnarson, Markus Sander Eckstrøm, Peter Rasmussen, Sebastian Juel Milo, Tue Elhegn, Victor Bielefelt Søndergaard
**Related backlog items.** MET-B-023, MET-B-010, MET-B-020

## Context

The system is expected to integrate with an existing authentication solution, such as INTRA, which already handles user authentication and login management. As user authentication is handled externally, the system needs an independent approach to managing authorization and controlling access to its functionality. Role-Based Access Control (RBAC) was considered as an alternative. However, integrating and maintaining a role-based structure alongside the existing authentication infrastructure would introduce an additional layer of role management within our system. A permission-based approach allows the system to manage authorization independently of the external authentication solution, without relying on roles provided by the existing infrastructure.

## Decision

We will implement a Permission-Based Access Control approach, where authorization is managed internally through permissions assigned to individual users. The existing authentication solution will remain responsible for verifying user identities, while our system will handle authorization by checking whether users possess the required permissions before allowing access to specific functionality.

## Consequences

Positive impact

Separating authentication from authorization allows the system to integrate with the existing login infrastructure without depending on its role management. Permissions can be managed independently within our system, providing flexibility when defining and modifying user access.

Potential drawbacks

The system becomes responsible for managing and maintaining user permissions internally. This requires additional administrative functionality and consistent enforcement of permission checks throughout the backend.

## Alternatives considered
Role-Based Access Control (RBAC). Was considered as an alternative, where permissions are grouped into predefined roles assigned to users. However, since authentication is already handled by an external system, introducing a separate role management structure was considered unnecessary for our current requirements.
